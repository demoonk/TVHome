# TVHome 2.0.5

TVHome 2.0.5 устанавливается поверх 2.0.4 с сохранением данных. Идентификатор приложения `ru.pda.tvhome` и исходный ключ подписи сохранены.

## Как ведёт себя ТВ

**После установки.** Home и голос настраиваются один раз. Перехват шестерёнки включается в настройках TVHome: «Система» → «Загрузка моста» → **«При старте Home»**. До перезагрузки мост работает сразу.

**После перезагрузки.** ТВ загружается как обычно; через 30–40 секунд после появления Home, когда лаунчер уже прогрузился, ТВ один раз показывает диалог «Разрешить отладку?». Нажмите **«Разрешить»** — мост запустится сам, шестерёнка заработает. На компьютере ничего запускать не нужно. Если диалог не подтвердить, мост не стартует. На этой прошивке ключ не сохраняется между загрузками, поэтому одно подтверждение при каждой загрузке — ожидаемое поведение.

Установщик `Setup-TVHome.ps1` ставит и аддон помощника (`bridge-helper-<версия>.apk`, SHA-256 проверяется), без него автозапуск после перезагрузки невозможен.

## Что нового в лаунчере

- Нажатие на карточку в поиске открывает тот адрес, который приложение объявило само. Правила собраны в `SearchCardRules` и проверены на ТВ в гостиной (192.168.1.7) 2026-11-09 командами `content query` и `cmd package query-activities`:
  - NUM — строка несёт id и тип, работает app-link `themoviedb.org` (было единственным работающим случаем);
  - РешалаТВ — строка несёт собственный deeplink `reshala://open?screen=card:tmdb://movie/<id>`, провайдер `reshala.tv.app.poisk` отвечает только на `/search_suggest_query` без `/search`; ранее приложение исключалось из чтения результатов, поэтому карточек не было;
  - SmartTube — открывается только строка, у которой в `suggest_intent_data_id` есть настоящий видео-идентификатор. Реальные строки его не несут, поэтому ничего не выдумывается;
  - Кинопоиск и VK Видео — карточки берутся из веб-выдачи на хостах, которые приложения зарегистрировали в своих intent-filter (`hd.kinopoisk.ru/film/<id>`, `vk.com/video-…`). Провайдер Кинопоиска отвечает `Unknown uri` на стандартном suggest-пути, провайдер VK требует `GLOBAL_SEARCH`, провайдер Vimu не экспортирован, КИОН отвечает пустой выдачей — карточек из провайдера там нет.
- Строка без проверенного целевого адреса уходит на exported search активность приложения, а её идентификатор передаётся через `SearchManager.EXTRA_DATA_KEY`, иначе приложение вообще не получает id строки.
- Boosty добавлен в проверенные поисковые входы: `https://vkplay.live/search?query=` резолвится в `live.boosty.tv.main.MainTvActivity`. Кнопка «Искать в …» по-прежнему обещает поиск только там, где вход или exported активность действительно проверены.
- Добавлены тесты на то, что любой путь в поиске ведёт к проверенному механизму: `SearchCardRulesTest` (JVM), `tests/test_search_card_rules.py` (harness без android.jar, сверяет правила и источник клика) и `tools/Verify-SearchLaunch.ps1` (проверка на самом ТВ: провайдер отвечает по правилу, каждый вход резолвится внутри приложения, поисковые активности экспортированы). Поведение интерфейса — открывается ли карточка, а не только резолвится интент — требует проверки на ТВ; в этой сессии приложения не выходили на передний план из adb.

## Мост шестерёнки и помощник

- Помощник `bridge-helper` 1.7 исправляет авторизацию adbd: ключ отправляется стандартным порядком AUTH (challenge → подпись → ключ), а не подменяется подписью. Раньше в диалоге показывалась 256-байтная подпись, framework писал `error doing base64 decoding`, и настоящий ключ не авторизовывался.
- Загрузка моста при старте Home отложена: запрос уходит через 30 секунд после первого кадра и только когда плитки загружены и Home в фокусе. Диалог ADB больше не появляется поверх ещё не готового лаунчера.
- `tvhome-bridge-ensure.sh` даёт `setsid` время отсоединиться (пауза 1 секунда), иначе guard погибал, не записав pid, когда клиент 1.7 сразу закрывал сессию после `CLSE`.
- `AdbClient` корректно читает конец shell-потока (`CLSE`), а не несуществующую команду `CLOSE`.

## Установщик

- `Setup-TVHome.ps1` сохранён с UTF-8 BOM: Windows PowerShell 5.1 без BOM читает файл как ANSI и не разбирает русский текст. У опубликованного ассета 2.0.5 BOM пропал — исправлено хотфиксом ассета, добавлен регрессионный тест.
- На прошивках, которые не отдают роль главного экрана (DEXP Q-серия), установщик больше не падает на назначении Home и не отключает Google Home: иначе ТВ оставался без рабочего Home. Он продолжает настройку голоса и моста и просит назначить TVHome главным экраном вручную (системные настройки или Button Mapper).
- Ответ `Warning: Activity not started` при повторном запуске TVHome считается успешным запуском, а не ошибкой.

## Проверки

320 JVM-тестов лаунчера (0 отказов), 24 теста помощника (0 отказов), 78 тестов установщиков (0 отказов), `lintRelease` — 0 ошибок. Мост и шестерёнка проверены на ТВ в гостиной (Android 14, Ventura G4FFDVB87) 2026-11-11: после подтверждения мост запускается, шестерёнка перехватывается.

Для установки скачайте **TVHome-2.0.5.apk**. `update.json` используется встроенной проверкой обновлений.
