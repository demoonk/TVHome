# Переход на TVHome 2.0.0

Основные исходники и тесты находятся в `launcher/app/src/{main,test}/java/ru/pda/tvhome`. Android package и namespace — `ru.pda.tvhome`.

В старом Java-пакете оставлены только пять коротких совместимых входов для ранее выбранных системных служб. Старые имена запуска Home и поиска сохранены как activity-alias. Это позволяет установленным мостикам пульта и Android пережить обновление без удаления приложения. Выбранные собственные компоненты автоматически переводятся на новые имена при обновлении и открытии Home, если приложению ранее предоставлено WRITE_SECURE_SETTINGS. Службы, которые не были выбраны, не включаются.

Идентификаторы broadcast/extra сохранены: это протокол взаимодействия, он не обязан совпадать с Java-пакетом.

## Изменения

- Удалена анимация возврата приложения в плитку и создание снимка плитки для неё.
- Запрос поиска редактируется; кнопка «Найти» и действие поиска клавиатуры повторяют поиск.
- Удалены кнопки перехода к поиску на сайте. Получение карточек с сайтов осталось.
- Окно поиска сохраняется за запущенным приложением вместе с карточками и выбранным результатом.
- При ожидании результатов и постеров показаны стандартные Android ProgressBar; они убираются при завершении, ошибке и тайм-ауте.
- Холодный запуск Home выбирает первую плитку; возвращение и пересоздание Home восстанавливают выбранное приложение по стабильному ключу. Если приложение исчезло, выбирается первая плитка.
- Координаты селектора уточняются по фактической разметке; события промежуточной привязки плиток не переписывают сохранённый выбор.
- Удалены старый SearchAppFan/SearchFanLayout, невызванные методы, старый countdown, перезаписываемые меню, неиспользуемые поля, импорты, две старые XML-анимации и 48 ключей строк с 430 локализованными определениями. Динамически адресуемые ресурсы сохранены.

## Возврат по физической кнопке Back

Некоторые приложения (например SmartTube) самостоятельно обрабатывают Back и открывают свой главный экран. Обычное сохранение Android back stack не может переопределить эту логику.

Для совместимого пульта TVC0GWBT существующий необязательный PQ-мостик дополнен возвратом в сохранённый поиск. Он только наблюдает evdev, не захватывает ввод и не включает accessibility-фильтр. Возврат активен только после запуска приложения из поиска; открытие Home или возвращение в поиск сбрасывает его.

На Windows после установки APK и авторизации ADB:

```powershell
./tools/Install-RemoteBridge.ps1 -Device TV_ADDRESS:PORT -Dex ./TVHome-remote-2.0.0.dex -Adb C:/platform-tools/adb.exe
```

DEX приложен к релизу; исходник — `tools/PqRemoteProof.java`. Мостик действует до перезагрузки ТВ. После перезагрузки его надо запустить снова. Несовместимые пульты скрипт отклоняет. Кнопку шестерёнки и удержание громкости проверяют физическим пультом.

Сборка DEX: `javac --release 8 -d bridge-classes tools/PqRemoteProof.java`, затем `jar cf bridge.jar -C bridge-classes .` и `d8 --min-api 26 --output bridge-dex bridge.jar` из Android Build-tools. Используется `bridge-dex/classes.dex`.

## Откат

Не удалять приложение и не очищать данные. Android обычно запрещает установку APK с меньшим versionCode. Для отката собирают сохранённые исходники 1.4.23 с тем же ключом подписи и versionCode выше установленного; затем выполняют `install -r`. Системные ссылки Home и помощника при возврате на 1.x переводят обратно на имена `com.gathin.tvhome`. Старый APK сам по себе не является гарантированным способом понизить версию.
